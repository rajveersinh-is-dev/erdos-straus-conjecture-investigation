# Incident: loss of the first working directory

Recorded because it affects reproducibility and because honesty about what
happened is part of the research record.

## What happened

* Session began in `C:\Users\davea\Downloads\proj2\o`, which was empty.
* `git init` there produced commit `0f79064` ("research: set up exact-arithmetic
  criterion and structural exploration"), containing `src/es_theory.py`,
  five experiment scripts and `research/research_log.md`.
* A long exact computation was launched in the background. It completed
  successfully and wrote `results/resistant_instances.json` (this file
  survived).
* When the next command was issued, the directory contained **only**
  `results/resistant_instances.json`. The `.git` directory was gone, `git`
  commands resolved to a repository at the **parent** directory
  `C:\Users\davea\Downloads\proj2`, whose history and remote belong to a
  different project (`erdos-problem-536-lcm-sets`), with commits about
  "Erdős Problem #536" and "f(N) >= N/2 + log_2(N) - 1".
* `git reflog` shows that repository's history starting from its own initial
  commit; our commit `0f79064` appears nowhere in it.

## Diagnosis

A **concurrent process** was using `C:\Users\davea\Downloads\proj2` as its
workspace and replaced/reset its contents. Nothing in our command history does
this: the only non-read operation was `Start-Process python experiments\...`,
which ran a computation to completion (its output file proves it) and cannot
delete unrelated files.

## Response

1. **Nothing belonging to the other project was touched.** We did not read,
   edit, commit or delete any file under `C:\Users\davea\Downloads\proj2\o`
   after detecting the change; the project lives in the *parent* repository,
   which we left entirely alone.
2. The work was **rebuilt from scratch** in
   `C:\Users\davea\AppData\Local\Temp\opencode\erdoes-straus`, outside the
   other repository's tree.
3. The GitHub repository `rajveersinh-is-dev/erdos-straus-conjecture-investigation`
   (created at the start of the session, never pushed to before the incident)
   was used as the destination for the rebuilt work.

## Consequences for the record

* Every file in this repository is a **fresh reconstruction**, not a recovery.
  Results computed in the lost directory are reproduced by the scripts here
  (all numbers quoted in the README and paper were re-derived after the
  incident) — except where explicitly noted.
* `results/resistant_instances.json` is the one artifact carried over from the
  lost directory; it was regenerated by `experiments/exp05_obstruction.py` and
  agrees with it.
